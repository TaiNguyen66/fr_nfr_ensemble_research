# How Much Does Evaluation Leakage Inflate FR/NFR Requirements Classification?

_A Leakage-Aware Re-Evaluation of Single and Ensemble Classifiers_

Nguyen Phat Tai, Hoang Anh · FPT University, Ho Chi Minh City · SWR302 (FA26)

Vietnamese version: [`README.vi.md`](README.vi.md)

This repository contains the code, protocol, split indices, per-fold scores and paper source for our study of how evaluation choices change the reported performance of functional (FR) and non-functional (NFR) requirements classifiers.

## Paper versions

| Folder | Version | Format |
|---|---|---|
| `paper/` | Course report for SWR302 (FA26) | IEEE conference (IEEEtran), 8 pages |
| `paper_iciit/` | Submission to ICIIT 2027 (12th International Conference on Intelligent Information Technology, Ho Chi Minh City, 4–7 March 2027) | ACM `sigconf` (acmart), 8 pages |

Both versions share the same text, numbers, tables and figures. They differ in document class and front matter (the ACM version adds CCS concepts and keywords and has no acknowledgment section) and in where some tables are placed. See [`paper_iciit/README.md`](paper_iciit/README.md).

## Research questions

- **RQ1.** How much do performance estimates and model rankings change when (a) duplicate and near-duplicate requirements are kept in the same fold (G-dup), and (b) all requirements of a project are kept in the same fold (G-proj), compared with stratified random CV (S)?
- **RQ2.** How much does oversampling the whole dataset before splitting (BEFORE) inflate performance estimates compared with oversampling only the training part of each fold (IN-FOLD)?
- **RQ3.** Under leakage-aware evaluation (G-dup), do hard voting (M5) and stacking (M6) outperform the single classifiers M1–M4?

## Main results (macro-F1)

| Comparison                        | Result                                                     |
| --------------------------------- | ---------------------------------------------------------- |
| RQ2, 12 classes: BEFORE − IN-FOLD | +0.392 to +0.491 (BEFORE 0.951–0.994, IN-FOLD 0.495–0.597) |
| RQ2, binary: BEFORE − IN-FOLD     | +0.015 to +0.027                                           |
| RQ1(b): S − G-proj                | 0.134 to 0.190; model ranking changes (Kendall τ = 0.600)  |
| RQ1(a): S − G-dup                 | below 0.01 for every model (only 8 duplicate groups)       |
| RQ3: ensembles vs single models   | clearly better than random forest only (+0.032, +0.042)    |
| Replication (Dalpiaz et al.)      | BEFORE − IN-FOLD +0.034 to +0.081; S − LODO 0.21 to 0.31   |

RQ1, RQ2 and the replication compare different test folds and are reported descriptively. Only RQ3, where models share the same splits, uses the corrected repeated k-fold t-test with Holm adjustment (amendment A-009).

## Reproducing the results

Python 3.12 on Windows (win-amd64); package versions are pinned in `requirements.txt`.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

# place the raw data in data/raw/ (see data/README.md), then:
python -m pytest -q tests                      # 37 tests
python -m src.audit_dataset                    # builds data/processed/
python -m src.run_experiments --plan RQ1       # 525 fold fits
python -m src.run_experiments --plan RQ2       # 1250 fold fits
python -m src.run_experiments --plan D2        # 770 fold fits
python -m src.analyze_results                  # results/tables, results/figures
python -m src.paper_tables                     # paper/tables, paper/figures/summary_deltas
```

A complete re-run on 2026-10-18 reproduced every fold score bit for bit (identical SHA-256 of all `fold_scores_*.csv`). The run guide with expected outputs and timings is in [`HUONG_DAN_CHAY_THI_NGHIEM.md`](HUONG_DAN_CHAY_THI_NGHIEM.md).
